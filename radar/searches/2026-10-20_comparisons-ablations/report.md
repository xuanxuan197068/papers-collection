## 2. 逐篇看：它比较了什么，怎样做消融，能借鉴什么

### USENIX Security

**① CPDS — Cyber-Physical Deception Through Coordinated IoT Honeypots（2025；ID 4147；F）**

- **对比设计：** 不只与其他蜜罐比，还加入真实设备。§5.2 的跨设备场景比较真实 IoT、CPDS、彼此不协调的独立蜜罐；参与者通过交互判断真伪。摄像头、扬声器、灯泡的反馈是否相互吻合，是关键检验点。
- **消融：** 跨设备场景里的“无协调蜜罐”直接检验协调机制。另一场景还改变摄像头视频表现，包含多项增强，不能把其全部收益归因于协调。
- **指标／证据：** 真伪判断、交互有效性；另测设备数量变化下的延迟和资源开销。后者属于扩展性测试。
- **可迁移：** 你的多主机蜜罐应检查文件、身份、网络拓扑和时间线的一致性，并设置“所有主机各自回复，但不共享状态”的对照。
- **阅读提醒：** §5.2 正文的部分人数与 Table 4 不一致；如复用成功率，应以明确的表格分母重新计算，不能直接拼接正文数字。

来源：[正式论文 §5.1–5.3、Table 4、Fig. 14，PDF 第 13–15 页附近](https://www.usenix.org/system/files/usenixsecurity25-guan.pdf)。

**② CHeaT — Cloak, Honey, Trap: Proactive Defenses Against LLM Agents（2025；ID 4535；F）**

- **对比设计：** 覆盖 PentestGPT、AutoAttacker、PenHeal，以及不同模型后端。先让攻击者在无防御环境完成 CTF，再测试加入防御后的结果；细粒度测试还覆盖不同输入位置和欺骗技术。
- **消融性质：** 单独测试技术类别，是技术效果分解；上下文增强、预处理、系统提示加固、微调等是适应性攻击者／防御鲁棒性设置，不应全部称为组件消融。
- **关键控制：** 部分困难任务在无防御时就无法完成，不能将这些任务上的失败都记成防御贡献。
- **可迁移：** 先证明攻击智能体会攻，再比较它是否被诱导、偏离目标、暴露额外行为。攻击失败与情报增加应分别报告。

来源：[正式论文 §6–7、Tables 3–4，PDF 第 11–14 页](https://www.usenix.org/system/files/usenixsecurity25-ayzenshteyn.pdf)。

### ACM CCS

**③ HoneyPLC — A Next-Generation Honeypot for Industrial Control Systems（2020；ID 3153；F）**

- **对比设计：** 以真实 PLC 为真实性参照，并与 Conpot、S7commTrace 等现有蜜罐比较。评价包括 Nmap／PLCScan 指纹、Shodan HoneyScore、工程软件的连接及程序块操作，最后补充长期在线观测。
- **消融：** 正文未确认完整的逐组件去除实验。系统对比、协议功能覆盖、线上部署不能改称消融。
- **指标：** 是否被识别成真实设备、是否支持深入交互，以及实际收集的交互日志。个别基线崩溃或未被索引是缺失结果，不能记作零分。
- **可迁移：** 做三层证据：自动探测像不像、真实工具能不能持续操作、线上是否产生有意义的后续行为。流量体积本身不等于情报价值。

来源：[作者全文 §5.4–5.7，PDF 第 7–11 页附近](https://carlosrubiomedrano.com/publications/honeyPLC-next-generation-ccs2020.pdf)。

**④ SUB-PLAY — Adversarial Policies against Partially Observed Multi-Agent Reinforcement Learning Systems（2024；ID 2089；F）**

- **对比设计：** 在 Predator-prey、World Communication 等环境比较启发式、Self-play、Victim-play，改变距离／区域等观测限制，以受害策略的任务表现衡量攻击效果。
- **消融：** §5.3、Table 2 检验 Subgame Construction（SC）、Transition Dissemination（TD）、Policy Meritocracy（PM）及其组合，展示结构划分、经验传播和策略筛选的贡献。
- **额外测试：** 不同观测条件下迁移、扩展性与成本，属于泛化和资源测试。
- **可迁移：** 如果蜜罐策略面对只能看到部分环境的攻击者，测试“不同可见信息”及策略迁移；经验共享应单独消融。这里是多智能体仿真，不是网络蜜罐效果的直接证据。

来源：[作者全文 §5.1–5.4、Table 2](https://arxiv.org/html/2402.03741)。

### IEEE S&P

**⑤ Incalmo — an Autonomous LLM-Assisted System for Red Teaming Multi-Host Networks（2026；ID 244；F）**

- **对比设计：** 使用 MHBench 多主机环境；与 ExpertPromptShell 比较时控制模型后端。完整比较覆盖 40 个环境，每环境 5 次、每次 75 分钟；模型和消融分析有较小的环境子集，不能宣称全部模型都跑过完整矩阵。
- **消融：** Incalmo-WHT 去掉高层任务接口、改用低层任务；Incalmo-WS 使规划器无法访问环境和攻击图服务，但底层任务智能体仍使用这些服务，不能写成“系统彻底删除状态服务”。
- **指标：** Success 是多次尝试中是否至少一次拿到关键资产，Reliability 是尝试层面的可靠性，Total Acquisition 关注资产获取范围，三者分母不同。
- **可迁移：** 用足够强的多主机攻击者检验蜜罐，并拆开“规划接口”和“状态知识”贡献；不要用 best-of-5 成功率冒充单次成功率。

来源：[作者全文 v4 §V–VI、Figs. 12–13](https://arxiv.org/html/2501.16466v4)。本次使用与本地标题一致的更新版本，不混用早期预印本的环境数量。

**⑥ DEPCOMM — Graph Summarization on System Audit Logs for Attack Investigation（2022；ID 997；F）**

- **对比设计：** 6 个自建多步攻击与 8 个 DARPA TC 案例；与 NoDoze 比较调查摘要，与多种社区发现方法比较社区质量，还检查与 HOLMES 的配合。
- **组件评价：** 分别检查社区发现、压缩、InfoPath 排序和耗时。压缩前后比较节点／边数量，同时核验 InfoPaths 未改变；这比仅报告“日志减少了多少”更有说服力。不同社区算法的比较不等于只替换一个内部模块的严格消融。
- **指标：** 社区 F1、攻击信息保留、Top-k 路径可解释性、压缩率、运行时间。
- **可迁移：** 蜜罐情报摘要必须证明关键事件和因果关系保留下来；建议比较原始日志、规则摘要、通用 LLM 摘要、你的证据图摘要。

来源：[作者全文实验部分 RQ1–RQ6、Tables VI–VIII、Figs. 10–11，PDF 第 10–14 页](https://par.nsf.gov/servlets/purl/10287251)。

### NDSS

**⑦ Chimera — Harnessing Multi-Agent LLMs for Automatic Insider Threat Simulation（2026；ID 6598；F）**

- **对比设计：** 在技术、金融、医疗等企业场景生成多角色行为，用专家判断与定量分析检验真实性，再用检测器检验数据的下游用途；比较涉及 ChimeraLog、CERT、TWOS，但各数据集并非参与每个实验。
- **下游验证：** SVM、CNN、GCN、DS-IID 等检测器，在同数据集与跨数据集设置下评估，并重复实验。不同基础模型也有比较。
- **消融：** 正文未确认系统性“去掉某个角色／记忆／规划模块”的消融；换模型和跨数据集测试不能代替这一点。
- **可迁移：** 蜜罐生成的行为或情报可同时接受专家真实性检查和下游检测／调查验证。更难被检测的数据，不自动等于更真实的数据。

来源：[NDSS 正式版本 §V–VI、Tables IV–VII](https://www.ndss-symposium.org/wp-content/uploads/2026-f375-paper.pdf)。采用正式版本，不混入早期 arXiv 的数值。

**⑧ HoneySat — A Network-based Satellite Honeypot Framework（2026；ID 6653；F）**

- **对比设计：** 先按 SPACE-SHIELD 检查攻击技术的可实现范围，再由 10 位有经验的卫星操作者完成任务、评价逼真度，辅以在线交互和扩展协议的验证。
- **关键边界：** 专家知道自己面对仿真环境，所以评分是逼真度评价，不能转述成盲测欺骗成功率。威胁框架中的“可适用技术”也不等于全部已实现。
- **消融：** 未确认经典的组件去除实验；核心是功能、专家和实地观测的多类证据。
- **可迁移：** 在缺少同领域可运行基线时，先建立真实业务任务与协议行为的评价标准，并明确哪些是真实交互、哪些是专家主观判断。

来源：[正式论文 §VI，PDF 第 7–12 页附近](https://www.ndss-symposium.org/wp-content/uploads/2026-f537-paper.pdf)。

### ASE

**⑨ MARG — Can Cooperative Multi-Agent Reinforcement Learning Boost Automatic Web Testing?（2024；ID 8269；F）**

- **对比设计：** 9 个网站，比较 WebExplor、QExplore 与相同智能体数量的独立 Q-learning（IQL_N），以及不同协作方式。固定 2 小时时间预算，重复 3 次。
- **消融／结构对照：** 同样 N 个智能体，独立学习对照共享／交流学习，可区分“多开几个智能体”和“协作机制”的收益；另改变智能体数量。
- **指标：** 状态、动作、故障覆盖，通信和信息传播成本。相同运行时长并不意味着相同总算力，资源成本还需单列。
- **可迁移：** 多蜜罐协作必须比较“相同数量但不交换情报”的版本。否则无法判断收益来自协作还是预算增加。

来源：[作者全文 §5–6](https://yepangliu.github.io/files/ASE2024-MARG.pdf)。

**⑩ SE-Jury — An LLM-as-Ensemble-Judge Metric for Narrowing the Gap with Human Evaluation in SE（2025；ID 8084；F）**

- **对比设计：** 比较单一评审策略、集成策略以及不同模型，考察与人类判断的相关性／一致性和成本。
- **消融：** “无 Team Selection”使用全部策略的简单集成；再同时取消策略选择与定制策略，退回普通提示。后一步是组合移除，不能解释成两个互相独立的单因素效应。
- **关键控制：** 用于选择策略的少量带标签样本与测试样本分开；另借可执行测试结果检验评价可靠性。
- **可迁移：** 给情报摘要打分的 LLM 评审器需要独立人工标注校准；不能既用同一批样本优化评分提示，又报告其测试一致性。

来源：[作者全文 §IV–V，尤其组件与样本规模分析](https://arxiv.org/html/2505.20854)。

### ICSE

**⑪ AutoRestTest — A Multi-Agent Approach for REST API Testing with Semantic Graphs and LLM-Driven Inputs（2025；ID 9757；F）**

- **对比设计：** 12 个 REST 服务，与 ARAT-RL、EvoMaster、MoRest、RESTler 比较；使用 RESTGPT 增强的规范减轻输入信息不对等。每次 1 小时，重复 10 次。
- **消融：** 去 LLM 输入生成、去 temporal-difference Q-learning、去语义属性依赖图 SPDG。作者明确保留智能体骨架，因此“Without Learning”不是“删掉多智能体”。
- **指标：** 方法／行／分支覆盖、操作覆盖和失败响应；HTTP 500 不自动等于独立安全漏洞。
- **可迁移：** 为蜜罐设计“策略不再更新但仍能正常运行”“取消依赖图但接口可用”的消融，比直接删掉整个执行链更能解释收益。

来源：[作者全文 §IV、Table IV](https://arxiv.org/html/2411.07098)。

**⑫ SIDE — Evaluating Code Summarization Techniques: A New Metric and an Empirical Characterization（2024；ID 10110；F）**

- **对比设计：** 用 5,201 条开发者评价比较包括 SIDE 在内的 40 种指标，涉及简洁性、流畅性、内容充分性等，分析指标间关系和对人工评价的解释力。
- **消融：** 对比训练时加入 hard negatives 与只用随机负例；§5.2 报告影响很小，主要研究发现没有因此改变。
- **值得学的地方：** 消融无明显提升也应如实呈现，不能因模块“理论上重要”就选择性忽略结果。
- **可迁移：** 情报摘要要分别评价内容覆盖、事实正确、冗余和可读性，不能仅凭与参考文本词汇相似就判定有效。代码领域的评测结论仍需在安全情报数据上重验证。

来源：[作者全文 §4、§5.2](https://arxiv.org/html/2312.15475)。

### ISSTA

**⑬ MASTest — Enhancing Multi-agent System Testing with Diversity-Guided Exploration and Adaptive Critical State Exploitation（2024；ID 11675；A）**

- **为什么选：** 同时关注多智能体行为多样性和关键状态，对“如何让攻击者暴露更丰富行为”的测试设计有启发。
- **已确认范围：** 摘要描述多样性引导探索与关键状态利用。全文入口未取得可读内容；作者单位海报被搜索引擎索引，但直接访问返回 404，不能当作已读海报。
- **未确认：** 基线名单、预算、重复次数、确切消融组合与表格数字，均不填写。
- **后续核查问题：** 是否分别去掉个体／群体多样性、关键状态选择及扰动自适应；是否同时报告不同失败类型和发现总数。这里是阅读问题，**不是原文结论**。

来源：[会议官方摘要与论文身份](https://2024.issta.org/details/issta-2024-papers/119/Enhancing-Multi-agent-System-Testing-with-Diversity-Guided-Exploration-and-Adaptive-C)。

**⑭ Can LLMs Replace Human Evaluators? An Empirical Study of LLM-as-a-Judge in Software Engineering（2025；ID 11535；F）**

- **对比设计：** 在代码翻译、生成和摘要三类任务，对比传统指标、嵌入／概率指标、直接 LLM 打分及不同评审策略，与人工标签计算相关性。
- **实验性质：** 这是评测实证研究，不是一个新模块系统的常规消融。额外比较逐个打分与成对选择，并交换答案先后顺序，测判断是否一致。
- **可迁移：** 情报质量盲评时隐藏方法名、交换候选输出顺序，单独测位置偏差；评审器在代码生成上的好表现，不能直接迁移成情报摘要的有效性证明。

来源：[作者全文 §4–5、RQ1–RQ3](https://arxiv.org/html/2502.06193)。

### FSE

**⑮ Getting pwn’d by AI: Penetration Testing with Large Language Models（2023；ID 12919；F）**

- **实验设计：** 探索性原型，分别研究高层辅助和低层执行；低层在刻意配置脆弱点的 Linux 虚拟机里执行“建议—执行—反馈”的闭环，并记录行为，重复多次观察稳定性。
- **比较与消融边界：** 文中讨论与传统工具的差异，但不是现代大规模基准下的完整 SOTA 对比；没有系统性模块消融。不能把展望里的记忆、反思等方案写成已经验证的模块。
- **可迁移：** 可作为廉价攻击闭环参照和失败案例分析来源；正式蜜罐实验应补上环境多样性、统一预算和更强攻击者。

来源：[作者全文 §3–5，尤其 PDF 第 3–4 页](https://arxiv.org/pdf/2308.00121)。

**⑯ MTAS — A Reference-Free Approach for Evaluating Abstractive Summarization Systems（2024；ID 12736；A）**

- **为什么选：** 情报常没有唯一参考摘要，MTAS 的无参考、蜕变关系评价与这个问题契合。
- **已确认范围：** 摘要提出利用输入变换及摘要一致性检查评价抽象摘要系统。
- **未确认：** ACM 全文请求返回 403，因此不列具体基线或消融结果。
- **迁移建议，非原文实验事实：** 给同一日志改排序、增加无关事件、做等价字段改名，再检查关键攻击事实是否保持；前提是该变换确实不改变安全语义，尤其不能随意打乱有因果含义的时间顺序。

来源：[会议官方页面](https://2024.esec-fse.org/details/fse-2024-research-papers/103/MTAS-A-Reference-Free-Approach-for-Evaluating-Abstractive-Summarization-Systems)、[论文 DOI](https://doi.org/10.1145/3660820)。

### ASPLOS

**⑰ FleetIO — Managing Multi-Tenant Cloud Storage with Multi-Agent Reinforcement Learning（2025；ID 14722；F）**

- **对比设计：** 原型系统上比较硬件隔离、软件隔离、SSDKeeper、基于历史窗口的自适应分配；联合看利用率与 P99 延迟，另测规模和负载切换。
- **消融：** FleetIO-Unified-Global 保留全局奖励但统一偏好参数；FleetIO-Customized-Local 保留个性化参数但只用本地奖励；完整版同时具备二者。可定位个性化权衡与全局协作激励的作用。
- **可迁移：** 如果你用强化学习优化蜜罐，可比较“单节点交互收益”和“整个网络的新增情报收益”，避免各节点重复套取相同信息。这里是奖励设计借鉴，不能把存储实验当作欺骗效果证明。

来源：[作者全文 §4.1–4.7、Fig. 15，PDF 第 9–12 页附近](https://snir.cs.illinois.edu/listed/fleetIO.pdf)。

**⑱ MulBERRY — Enabling Bit-Error Robustness for Energy-Efficient Multi-Agent Autonomous Systems（2024；ID 14945；S）**

- **已核对材料：** 作者会议报告幻灯片，未取得正式论文全文。
- **可确认设计：** 与 Classical MA 比较，改变电压和低电压智能体数量；同时看任务成功率、飞行距离／能耗和任务数量。第 52 页说明所报结果取 500 次运行平均；后续页逐步展示设备端方案及资源／协作优化。
- **消融边界：** 幻灯片展示递增加入优化的层次，但不足以完整核实每一步的实验控制及独立贡献，不将其整理成已确认的单因素消融表。
- **可迁移：** 对蜜罐“更便宜”的论证需同步报告任务质量；模型缩小、并发增加之后，情报量是否下降要一起看。

来源：[作者幻灯片，第 50–58 页](https://zishenwan.github.io/publication/ASPLOS24_mulberry_slide.pdf)。

### SOSP

**⑲ Potemkin — Scalability, fidelity, and containment in the potemkin virtual honeyfarm（2005；ID 14444；F）**

- **对比设计：** 用真实网络流量评估地址复用、所需 VM 数和资源需求；改变 VM 空闲回收时间，比较开／关扫描过滤。再拆解克隆、共享内存和网关成本。
- **消融／微基准：** 同一流量下开关 scan filter 是明确机制对照；Fork 与预分配域比较克隆时间。内存共享实验还报告实际克隆上限与容量外推，二者不能混用。
- **指标：** 平均／峰值活跃 VM、启动延迟、内存、CPU、网关开销。
- **可迁移：** LLM 蜜罐需测并发和冷启动；“节省资源”的策略是否漏掉有价值的会话，也应另作验证。这篇没有替你证明这一情报收益问题。

来源：[全文 §5、Fig. 5、Table 1，PDF 第 10–13 页附近](https://web.stanford.edu/class/archive/cs/cs240/cs240.1086/readings/potemkin.pdf)。

**⑳ Backtracking intrusions（2003；ID 14514；F）**

- **对比设计：** 使用真实蜜罐入侵案例和混有正常负载的自建攻击，比较过滤前后的依赖图，检查能否保留导致入侵的关键链条。
- **组件检验：** 逐步加入不同依赖过滤，减少无关节点／边；额外过滤可能影响证据范围，所以不能只比较图变小的程度。
- **控制开销的方式：** 用 ReVirt 重放同一执行轨迹，比较有无事件日志记录器，避免两次真人攻击不同而污染性能比较。
- **可迁移：** 情报去噪必须报告关键因果路径召回；确定性重放适合日志开销，交互策略会改变后续行为时，则不能用同一静态轨迹代替完整闭环效果实验。

来源：[SOSP 2003 正文 §5、Fig. 8，PDF 第 9–10 页附近](https://www.cs.rochester.edu/meetings/sosp2003/papers/p190-king.pdf)。未混用后来扩展的期刊版本。

## 3. 给你的实验方案：先形成三条证据链

以下是**结合文献提出的课题建议，不是上述论文已经共同验证的结论**。目前没有你的系统实现说明，因此具体模块以实际架构为准。

### 3.1 别把三个研究问题合成一个成功率

| 研究问题 | 推荐主指标 | 必要补充 | 主要参考 |
|---|---|---|---|
| RQ1：蜜罐是否可信且可持续交互？ | 跨轮次／跨主机状态矛盾率；预先定义任务的可完成率 | 盲测识别率、协议／工具兼容性；区分自然停止、识破退出和超时 | CPDS、HoneyPLC、HoneySat |
| RQ2：欺骗策略是否改变攻击者行为？ | 相比基线新增的有效行为／攻击阶段覆盖 | 实际目标达成率、偏离路径、首次识破时间、交互成本 | CHeaT、Incalmo、SUB-PLAY |
| RQ3：是否产生更多有用情报？ | 每会话新增且经核验的事实／TTP；关键事件与因果边的召回 | 精确率、重复率、证据可追溯率、分析员调查正确率及耗时 | DEPCOMM、Backtracker、SIDE |
| RQ4：上述收益是否值得成本？ | 每单位预算获得的有效情报，配合质量底线 | Token、费用、P95／P99 响应延迟、并发、失败／超时率 | FleetIO、Potemkin、MulBERRY |

“新增”应相对会话开始前或训练／已知情报集合定义，并明确是在单会话还是整个部署范围内去重。“攻击者多说了几句”与“出现了未被规则识别的新字符串”都不足以成为新情报。

受控环境可以用埋设事实、真实攻击轨迹和文件／网络证据定义 ground truth。线上开放环境通常没有完整真值，应保留“可证实／可反驳／暂无法判断”三类，不能把未被已知标签覆盖的内容一律算错，也不能把它们全部算新发现。模拟攻击者讲述的身份和意图也不能直接当真实标签。

### 3.2 主对比：每个基线回答一个问题

| 组别 | 配置 | 它回答的问题 |
|---|---|---|
| B0 传统规则／服务仿真蜜罐 | 能支持相同入口与基本任务的可运行实现 | 相比现有低成本系统，新增价值在哪里？ |
| B1 基础 LLM 蜜罐 | 相同后端、固定提示、有限会话历史 | 收益是否只是换成了 LLM？ |
| B2 有状态 LLM 蜜罐 | 持久状态／记忆，采用固定欺骗策略 | 学习或自适应策略是否真的必要？ |
| B3 独立多智能体蜜罐 | 相同节点和智能体数，各自工作，不交换状态／情报 | 协调机制是否优于简单并行？ |
| B4 完整系统 | 实际提出的方法 | 整体收益是否成立？ |
| R 真实服务／高保真环境 | 与蜜罐匹配的任务接口 | 用作真实性参照；不与蜜罐混算“情报采集冠军” |

B0 应按实际场景选可运行工具：PLC 场景的 HoneyPLC 不应直接充当普通 Linux shell 蜜罐基线。不同范式无法共享内部模块时，主系统对比报告可比能力边界；模块归因则依靠你自己的可运行变体。

固定攻击初始目标、拓扑、入口信息、随机种子集合和终止条件。LLM 组尽量用同模型版本、相同可用工具权限与总预算；同时报告“同时间”和“同费用／Token”结果，因为复杂协作通常消耗更多资源。禁止将完整系统额外获得的攻击真值、拓扑知识偷偷给成内部优势。

攻击者至少覆盖脚本、普通工具型智能体、具备多步规划／记忆的智能体。先跑无欺骗环境，报告每类攻击者的基础完成率；再在有能力完成的任务上比较干预效果，同时保留全任务集结果，避免筛选隐藏失败。选定攻击者后再冻结测试集；另留不同模型、拓扑和目标做泛化测试。

### 3.3 消融：每一个变体都应能正常执行

| 如果系统确有该模块 | 建议消融／替换 | 主要观察量 | 要避免的混淆 |
|---|---|---|---|
| 持久状态／世界模型 | 使用局部、固定窗口状态；保留可运行接口 | 跨轮次及跨主机矛盾率、任务完成率 | 删掉必要接口造成整体崩溃 |
| 多智能体协调 | 保持同样节点数和总预算，取消共享状态／消息 | 重复情报率、全局新增情报、冲突 | 完整版得到更多调用预算 |
| 自适应欺骗策略 | 固定策略；或关闭在线更新但保留执行器 | 有效诱导、信息收益、识破率 | 把无学习写成无智能体 |
| 攻击者意图推断 | 去推断，使用统一策略；保留其他观测 | 不同目标下的情报获取、误引导 | 真值标签泄漏给完整系统 |
| 情报奖励 | 全局增量奖励 vs 本地交互奖励；分别去掉新颖性／验证项 | 经核验新增事实、冗余、质量与费用 | 只测训练奖励，不测独立效用 |
| 证据校验／图摘要 | 通用摘要、无校验摘要、完整证据摘要 | 事实精确率、关键路径召回、调查效果 | 以同一个 LLM 同时生成并自评 |

若“持久状态”和“自适应策略”是主要创新，增加一个 **2×2** 组合实验：二者都无、仅状态、仅策略、二者都有。这能检查交互作用；单独逐项去除只能说明在其余模块存在时的条件贡献。对所有实际不存在的模块，直接删去对应行，不为填满消融表而设计虚假模块。

### 3.4 统计与情报评审

- 以**攻击会话／环境**为主要实验单元，命令和对话轮次通常不是独立样本。同一拓扑多次运行要保留层级关系。
- 先小规模试验估计方差，再决定重复次数。报告配对差值和区间；跨环境重采样应保留同一环境内的配对结构，不能把数万条日志当数万个独立实验。
- 固定超时、失败、退出的判定与计入方式。参与时长被上限截断时，应标记截断，不能把未结束会话都解释成持续成功诱骗。
- 将评分器校准样本与正式测试分开。可执行事实优先用状态和日志验证；主观指标用盲评，打乱输出顺序，抽样双人复核并报告分歧处理。
- 独立保留案例：成功诱导但无情报增益、情报丰富却被识破、交互很长却全是重复、摘要流畅但事实错误。这些能解释单一平均值掩盖的问题。

### 3.5 最值得先完成的五组实验

1. **真实服务／规则蜜罐／基础 LLM／完整系统的可信度对比**：协议任务 + 状态一致性 + 盲测。
2. **固定预算的主动情报获取对比**：主指标用经核验的新增事实与关键攻击阶段，不用对话长度代替。
3. **状态 × 策略的 2×2，以及同规模“无协调”变体**：识别核心机制和协作收益。
4. **更强／未见攻击者与未见拓扑**：先证明攻击者的无防御能力，再测欺骗的泛化。
5. **情报质量和成本联合评价**：精确率、路径召回、调查用途，加上费用、延迟及并发。

若资源有限，优先做第 2、3 组，并保留第 1 组的基本一致性检查。只有“诱骗更多”而没有“情报更好”，不足以支持以情报获取为核心贡献的论文。
